Tasks keep their original bucket and object scope when you navigate. Cancellation does not undo completed work.

Upload one file

The file goes through the local OC process. Storage credentials stay there.

You can enter a bucket even when your identity cannot list it. Storage checks the exact destination.

Slashes, spaces, and other characters are kept exactly as entered. The current prefix is only a suggested destination.

Create-only is the default. Replacement requires a separate confirmation.

Delete an exact key

Enter the destination directly when bucket browsing is unavailable. The server will prepare one key for review; nothing is deleted yet.

The key is kept exactly as entered. Authorization is checked when deletion executes.

Confirm replacement

This upload may replace the current object or create a new version, depending on storage settings. It does not protect against concurrent changes. Completed writes cannot be undone here.

The plan fixes object keys, not versions. Execution deletes the current object at each listed key. A same-key replacement made after planning may also be deleted. New keys outside this list are not included.
