# 阶段四 稳定性与生态

> 阶段实现与验证记录：本文保留编写时的源码背景、验证结果和限制。当前安装、容器与操作步骤见[文档目录](zh_CN/README.md)，支持范围见[兼容指南](zh_CN/compatibility.md)。早期阶段的待办状态不代表当前项目状态。

阶段四最初只改造 OC 客户端及其验证、发行和维护流程。管理 SDK 修改、SDK 拆分和独立发布仍暂缓，OC 的 SDK 固定版本及 go.mod/go.sum 保持不变。后续 OC/OtterIO 联合审查补充了服务端 HTTP、路径与资源释放修正；当前固定服务端基线需要 [兼容清单](compatibility.json) 中按顺序列出的三项补丁。

## 客户端取消与资源释放

`Watcher.Join` 在空闲接收、事件转发及错误转发时响应 context 取消。S3 通知转发也在接收、事件发送和错误发送时检查 context，并在退出时关闭输出通道。慢消费者停止读取后，取消不再让转发 goroutine 永久停在无缓冲 channel 发送上。

回归测试分别覆盖聚合 watcher 与 S3 转发器的空闲、阻塞事件、阻塞错误和上游通道关闭。竞态测试验证取消和转发并行发生时的行为；真实服务测试另验证 watch、trace 和 console 命令退出。

本地文件监听在接收、事件发送和错误发送时响应 context 取消及 `DoneChan` 关闭。单个转发协程负责关闭输出通道；命令退出及同步重试会等待监听停止，监听启动失败也会清理可能注册的资源。本地通知队列最多缓存 1000 条事件，不再动态增长。队列达到容量时保守判定事件历史可能不完整，返回 `WatchQueueSaturated`；无法从 notify 获得精确丢失条数。macOS FSEvents 的原生丢失、必须扫描及根目录变更信号会返回 `WatchEventsLost`。两者的 JSON 错误分类均为 `watch`，`watch` 与 `find --watch` 返回非零退出码，关闭事件通道不会掩盖缓冲中的终止错误。

文件状态读取由每个监听独立复用的 OC 辅助进程执行，只通过私有管道交换路径、大小、目录标记与错误，不加载用户配置，不写入文件。取消或队列饱和时关闭管道、终止并回收辅助进程，并等待管道读取协程退出，避免文件系统 syscall 阻塞事件转发协程的清理。辅助进程启动失败会作为监听错误报告。

本地源的 `mirror --watch` 在队列饱和或原生丢失通知后停止当前同步轮次、清理监听与复制线程，再注册新监听并重新核对源和目标。另默认每分钟核对一次，覆盖底层在应用队列之前合并、丢弃事件及异步监听启动窗口。可通过 `--watch-rescan-interval 5m` 调整周期，最小为 1 秒。事件丢失或订阅异常结束后的恢复轮次会重传源中现存的文件，包括大小和时间相同的文件。常规定期核对只比较元数据，不读取未变化对象的完整内容。深度校验默认关闭，可用 `--watch-verify-interval 1h` 独立设置周期（最小 1 秒，`0` 关闭）；到期后在下一次常规重扫中流式比较两端 SHA-256，仅重写内容变化的文件。深度校验仍会完整读取两端数据，并要求目标具有读取权限，应按目录大小和带宽调整周期；关闭时无法保证发现元数据相同的内容损坏。删除仍要求 `--remove`，排除项和时间筛选继续生效。真正的 `--active-active`/`--multi-master` 保留时间冲突判定，不以单向恢复覆盖另一侧的新版本；普通 `--watch` 不再被误设为 active-active 模式。恢复核对提供当前状态收敛，不是完整事件历史或短暂文件的持久化审计。聚合监听在上游订阅意外关闭时报告 `WatchStreamClosed`，镜像会报告故障并重新注册监听。

回归测试覆盖两种停止方式、阻塞状态读取与辅助进程回收、慢消费者、事件发送与取消并发、队列容量与 FIFO、终止错误传递、真实文件事件洪峰、原生丢失标记、同步溢出/周期恢复，以及真实 CLI 在没有源事件时修复同大小同时间的目标文件和清理残留。Linux、Windows 的原生运行结果仍需平台 CI 验证，交叉编译不替代运行验证。

命令收到 SIGTERM 后取消全局 context，等待命令及复制工作线程清理后以 143 退出；清理超过 3 秒则以 1 退出。OC 为自己创建的分片会话执行独立的、最多 2 秒的终止请求。真实 HTTP 测试确认订阅请求连接释放；SDK 内部资源的完整回收仍不能仅由进程退出证明。

OC 的管理日志命令现由客户端适配层接管响应体读取，关闭响应体并传播连接、EOF 和 JSON 解码错误。EOF 或损坏记录使命令明确失败，不自动重连；SDK 仅用于请求签名与发送，其日志解码和重连循环被停止。管理 trace 同样由 OC 适配层接管解码，EOF 和损坏记录返回 `TraceStreamClosed` 或解码错误，关闭响应体并停止 SDK 重连。SDK 固定版本保持不变。流式通知没有持久化游标，不承诺断线期间事件补发；需要完整事件历史时，应使用持久化通知目标及消费确认机制。

## 本地文件写入

本地复制为每次写入创建独立的私有暂存目录，数据与目标名记录分开存放。写入长度、时间属性及取消状态在重命名前检查，失败时保留原目标并清理本次暂存文件。未知长度使用 -1；长度为 0 表示空文件。

本地写入从创建到提交、清理均持有父目录及暂存目录句柄。目录路径被替换时，不会跟随替换后的符号链接或目录；提交使用相对于两个目录句柄的重命名，而不是重新解析源路径。发现暂存目录被替换后拒绝提交，清理仅移除原目录中的本次暂存数据，并返回错误；移走后的空目录及替换条目不会被按路径追踪删除。Windows 另验证目录所有者并设置私有 ACL。暂存清理失败会使命令报错，即使目标文件已提交，也不会输出成功状态。回归覆盖预置旧临时文件符号链接、写入中替换暂存目录、检查后替换源目录、父目录移动及清理失败。Windows 的运行结果仍需由 Windows CI 验证，交叉编译不能替代它。

`ls --incomplete` 和 `rm --incomplete` 同时支持带有效 OC 格式记录的新暂存目录与旧 `目标名.part.minio` 文件。目录名相似不足以授权清理；新格式还会检查目标名、目录内容与已列举文件的身份，拒绝符号链接或被替换的数据。普通列举与监听隐藏客户端暂存文件。旧 `.part.minio` 后缀继续作为历史临时文件约定。

显式指定符号链接目录时，可通过该路径列举与清理未完成文件；递归扫描不跟随子目录符号链接。仅剩目标名记录的崩溃残留也可清理。清理失败返回非零退出码，不向上删除用户目录。

## 诊断命令

```sh
oc --json doctor
oc --json doctor store
oc --json doctor --online store
```

默认离线，不发服务器请求。有别名时输出 S3/管理协议、是否分离管理地址、是否配置管理 CA 及证书验证设置；在线模式只查询管理 ServerInfo，使用 15 秒期限，额外输出节点数和服务器版本。

输出采用字段白名单，不序列化配置，不包含 endpoint 主机、路径、access key、secret key、session token、签名或配置目录。客户端版本、平台、Go 版本和嵌入的 SDK 版本来自当前二进制。在线失败只报告错误码和分类，退出非零，不输出 SDK 原始错误。离线诊断不能证明证书有效或连接可达；`certificateVerification` 仅表示客户端是否启用验证。

检查顺序：先用离线诊断确认协议、管理地址分离及 CA 设置，再用在线诊断确认管理连接；S3 的实际权限和数据操作仍需单独执行。共享诊断结果前，可按组织要求进一步移除平台及版本信息。

## 稳定性及性能基线

```sh
python3 buildscripts/test-core-integration.py \
  --oc /path/to/oc --otterio /path/to/otterio \
  --extended --stability --soak-seconds 60 \
  --report /tmp/oc-phase-four.json
```

`--stability-only` 在临时双端口独立 TLS 部署上运行核心功能与稳定性测试。测试使用独立配置、随机凭据、随机本地端口和临时数据目录，不连接已有用户服务。

验证范围：

- 65 MiB 对象，并发数 1 和 4 的上传与下载；下载后逐个核对 SHA-256。
- 记录总体墙钟耗时、总体 MiB/s 和各 OC 进程的 RSS 采样峰值。
- watch、trace、console 各进行三轮取消测试，先收到真实事件，再暂停消费；取消时恢复读取以释放阻塞写，必须在预算内以 143 退出。
- 大对象下载暂停读取后取消；65 MiB 上传（含 `--continue` 会话模式）通过限速中继，直接查询分片会话及已完成分片，确认分片字节数大于零后取消，核对无残留会话。
- 透明 TCP 中继限制下行速率为 8 MiB/s，TLS 及签名内容不变，下载后校验哈希。
- 下行经过 1 MiB 后断开一次连接；命令成功必须对应完整哈希，命令失败则显式重新下载并核对内容，避免把残留文件当成功。
- 上传经过 1 MiB 后断开一次连接，失败时显式重试，随后下载校验 SHA-256 并查询同一对象是否存在残留会话。
- 可选 watch 慢消费者持续采样，默认不开启，支持 0–3600 秒；CI 使用 30 秒，本地验收使用 60 秒。

所有测试预算统一读取 `compatibility.json` 并验证字段。吞吐不得低于 5 MiB/s，也不得比同主机同次运行的单次参考传输下降超过 50%；期限、RSS、取消和内存增长也由清单控制。上述预算用于发现严重回归，不代表优化后的性能目标。TCP 中继退出时必须释放监听器、连接和线程。

RSS 通过 Linux/macOS 的 ps 每 100 ms 采样，短命令的采样峰值可能低于真实瞬时峰值；它不是整棵进程树或服务器内存。墙钟吞吐包含 CLI 启动及本机文件系统开销，本地结果不能外推为生产环境或网络性能承诺。60 秒采样不能证明小时或天级稳定性。

报告记录操作、并发数、字节数、耗时、采样内存、取消状态、故障恢复及两个二进制的 SHA-256。失败报告保留当前场景的已完成指标、传输尝试、最近命令、异常分类及脱敏错误消息；临时服务日志在目录清理前脱敏保存。CI 无论成败均归档 JSON 与诊断目录。不能将部分通过报告作为完整验收。

## 本轮缺陷修复验证

`pipe` 将可能阻塞的继承标准输入放入一个独立辅助进程，主进程读取可取消的管道。取消会关闭管道、终止并回收辅助进程，然后清理本地 staging；正常 EOF 必须等待辅助进程成功退出。辅助进程只转发输入字节，不加载配置；独立存活管道每 100 ms 检测父进程是否仍在读取，父进程被 SIGKILL 终止且上游输入仍打开时，辅助进程也退出。SIGKILL 不执行父进程 defer，因此本地 staging 的残留仍由 incomplete 清理处理。每条 pipe 命令增加一个辅助进程，其资源不包含在仅统计主 OC 进程的 RSS 预算内。

镜像取消返回到统一信号处理入口，SIGINT/SIGTERM 保留 130/143。管理日志的连接、EOF 与解码错误由 OC 适配层传回命令入口，意外结束返回非零状态并回收响应体和生产协程；已解码的有效记录在结束前输出，慢消费者取消也释放资源。SDK 固定版本没有变更。S3 pipe 使用命令取消上下文中止网络请求，再以独立、最多 2 秒的清理上下文删除自己的分片会话；服务器不可达或拒绝清理时，命令报告清理错误，不承诺远端已删除。

新增回归覆盖订阅异常传播与镜像恢复、周期核对跳过相同内容及修复同大小损坏、正常 pipe EOF、本地 pipe 阻塞取消清理、镜像与 pipe 的 SIGINT/SIGTERM 退出码，以及管理日志不可达端点错误输出。后续回归另覆盖真实 S3 上传取消与分片删除、强制终止父进程后的辅助进程退出、日志 EOF/损坏 JSON 不重连、有效记录保留与响应体关闭。

## 流式与深度校验修正

`find --watch` 在订阅意外结束时输出 `WatchStreamClosed` 并返回非零状态。trace 回归测试覆盖有效记录保留、EOF/损坏 JSON 不重连、实时记录以及慢消费者取消时关闭响应体；镜像回归覆盖默认不启动深度校验、独立周期跨重扫保留，以及显式开启时的内容修复。

时间筛选在深度读取前执行，被 `--older-than` 或 `--newer-than` 排除的文件不参与内容校验。`find --watch` 的期限超时返回错误，主动取消沿用信号退出规则。镜像 URL 生成与差异比较的接收、发送均响应取消，每轮比较结束会停止其列表生产者，避免慢消费者或提前退出遗留扫描协程。

## OC/OtterIO 联合审查修正（2026-10-07）

OC 管理地址与配置导入统一校验主机、IPv6 和 1–65535 端口，拒绝空端口与空片段。JSON 致命错误先展开格式参数，配置缓存首次加载使用独占锁。Windows 目录订阅失败时释放初始句柄，通用写事件补充 LAST_WRITE，覆盖同尺寸原地改写。镜像实时创建事件沿用扫描的年龄筛选：本地读取文件修改时间，S3 启用年龄筛选时查询对象修改时间；实时创建、删除事件使用与扫描一致的相对排除路径。

OtterIO 修正管理查询交替项校验、对象名重复解码及 heal 前缀丢失。流完成或消费者关闭会取消请求上下文，清理订阅；上下文值使用快照，HealthInfo/Heal 生产者在取消后不再阻塞发送。请求计数覆盖处理函数及响应流；关闭使用一个期限，关闭监听会唤醒 Accept，合成监听地址不再修改真实地址。TLS 仅宣告服务实际支持的 HTTP/1.1。
