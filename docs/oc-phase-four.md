# 阶段四 稳定性与生态

本阶段只改造 OC 客户端及其验证、发行和维护流程。按用户要求，管理 SDK 修改、SDK 拆分和独立发布暂缓；OtterIO 服务端、OC 的 SDK 固定版本及 go.mod/go.sum 均保持不变。当前基线仍要求阶段二的管理查询桥接与阶段三的关闭、Darwin 重启补丁。

## 客户端取消与资源释放

`Watcher.Join` 在空闲接收、事件转发及错误转发时响应 context 取消。S3 通知转发也在接收、事件发送和错误发送时检查 context，并在退出时关闭输出通道。慢消费者停止读取后，取消不再让转发 goroutine 永久停在无缓冲 channel 发送上。

回归测试分别覆盖聚合 watcher 与 S3 转发器的空闲、阻塞事件、阻塞错误和上游通道关闭。竞态测试验证取消和转发并行发生时的行为；真实服务测试另验证 watch、trace 和 console 命令退出。

命令收到 SIGTERM 后取消全局 context，等待命令及复制工作线程清理后以 143 退出；清理超过 3 秒则以 1 退出。OC 为自己创建的分片会话执行独立的、最多 2 秒的终止请求。真实 HTTP 测试确认订阅请求连接释放；SDK 内部资源的完整回收仍不能仅由进程退出证明。

管理 SDK 的日志/trace 断流响应体关闭、EOF 重连节流及错误通道取消问题已记录，按用户指示不在本阶段处理。流式通知没有持久化游标，不承诺断线期间事件补发；需要完整事件历史时，应使用持久化通知目标及消费确认机制。

## 本地文件写入

本地复制为每次写入创建独立的私有暂存目录，数据与目标名记录分开存放。写入长度、时间属性及取消状态在重命名前检查，失败时保留原目标并清理本次暂存文件。未知长度使用 -1；长度为 0 表示空文件。

`ls --incomplete` 和 `rm --incomplete` 同时支持带有效 OC 格式记录的新暂存目录与旧 `目标名.part.minio` 文件。目录名相似不足以授权清理；新格式还会检查目标名、目录内容与已列举文件的身份，拒绝符号链接或被替换的数据。普通列举与监听隐藏客户端暂存文件。旧 `.part.minio` 后缀继续作为历史临时文件约定。

显式指定符号链接目录时，可通过该路径列举与清理未完成文件；递归扫描不跟随子目录符号链接。仅剩目标名记录的崩溃残留也可清理。清理失败返回非零退出码，不向上删除用户目录。

## 诊断命令

```sh
oc --json doctor
oc --json doctor store
oc --json doctor --online store
```

默认离线，不发服务器请求。有别名时输出 S3/管理协议、是否分离管理地址、是否配置管理 CA 及证书验证设置；在线模式只查询管理 ServerInfo，使用 15 秒期限，额外输出节点数和服务器版本。

输出采用字段白名单，不序列化配置，不包含 endpoint 主机、路径、access key、secret key、session token、签名或配置目录。客户端版本、平台、Go 版本和嵌入的 SDK 版本来自当前二进制。在线失败只报告错误码和分类，退出非零，不输出 SDK 原始错误。离线诊断不能证明证书有效或连接可达；`certificateVerification` 仅表示客户端是否启用验证。

检查顺序：先用离线诊断确认协议、管理地址分离及 CA 设置，再用在线诊断确认管理连接；S3 的实际权限和数据操作仍需单独执行。共享诊断结果前，可按组织要求进一步移除平台及版本信息。

## 稳定性及性能基线

```sh
python3 buildscripts/test-core-integration.py \
  --oc /path/to/oc --otterio /path/to/otterio \
  --extended --stability --soak-seconds 60 \
  --report /tmp/oc-phase-four.json
```

`--stability-only` 在临时双端口独立 TLS 部署上运行核心功能与稳定性测试。测试使用独立配置、随机凭据、随机本地端口和临时数据目录，不连接已有用户服务。

验证范围：

- 65 MiB 对象，并发数 1 和 4 的上传与下载；下载后逐个核对 SHA-256。
- 记录总体墙钟耗时、总体 MiB/s 和各 OC 进程的 RSS 采样峰值。
- watch、trace、console 各进行三轮取消测试，先收到真实事件，再暂停消费；取消时恢复读取以释放阻塞写，必须在预算内以 143 退出。
- 大对象下载暂停读取后取消；65 MiB 上传（含 `--continue` 会话模式）通过限速中继，直接查询分片会话及已完成分片，确认分片字节数大于零后取消，核对无残留会话。
- 透明 TCP 中继限制下行速率为 8 MiB/s，TLS 及签名内容不变，下载后校验哈希。
- 下行经过 1 MiB 后断开一次连接；命令成功必须对应完整哈希，命令失败则显式重新下载并核对内容，避免把残留文件当成功。
- 上传经过 1 MiB 后断开一次连接，失败时显式重试，随后下载校验 SHA-256 并查询同一对象是否存在残留会话。
- 可选 watch 慢消费者持续采样，默认不开启，支持 0–3600 秒；CI 使用 30 秒，本地验收使用 60 秒。

所有测试预算统一读取 `compatibility.json` 并验证字段。吞吐不得低于 5 MiB/s，也不得比同主机同次运行的单次参考传输下降超过 50%；期限、RSS、取消和内存增长也由清单控制。上述预算用于发现严重回归，不代表优化后的性能目标。TCP 中继退出时必须释放监听器、连接和线程。

RSS 通过 Linux/macOS 的 ps 每 100 ms 采样，短命令的采样峰值可能低于真实瞬时峰值；它不是整棵进程树或服务器内存。墙钟吞吐包含 CLI 启动及本机文件系统开销，本地结果不能外推为生产环境或网络性能承诺。60 秒采样不能证明小时或天级稳定性。

报告记录操作、并发数、字节数、耗时、采样内存、取消状态、故障恢复及两个二进制的 SHA-256。失败报告保留当前场景的已完成指标、传输尝试、最近命令、异常分类及脱敏错误消息；临时服务日志在目录清理前脱敏保存。CI 无论成败均归档 JSON 与诊断目录。不能将部分通过报告作为完整验收。

## 平台与发行维护

交叉编译补齐 Linux amd64 和 Windows arm64，共 11 个目标。Windows arm64 已加入发行配置。交叉编译只验证可构建；Windows/FreeBSD 等未进行真实服务联调的目标不承诺相同运行验证等级。

现有 CI 继续在 Linux、macOS、Windows 运行单元测试，Linux/macOS 的 CGO=0/1 集成矩阵增加稳定性和 30 秒采样。远程执行结果以 CI 实际报告为准。

```sh
python3 buildscripts/generate-sbom.py \
  --binary /path/to/oc --output /tmp/oc.cdx.json
```

生成 CycloneDX 1.6 格式的已编译 Go 模块清单，含二进制 SHA-256、Go 版本、模块版本和模块校验信息。来源为 `go version -m -json`，不扫描用户配置。它是二进制模块清单，不包含逐包调用图、许可证判定或漏洞结论。

发行前加 `--require-clean`，要求完整 VCS revision/time 和 `vcs.modified=false`，拒绝缺失信息、脏源码构建和依赖替换；每个平台产物应分别生成清单并随校验文件归档。本阶段验证脚本拒绝脏构建；实际发布仍按阶段一保持禁用，没有上传或发布外部资源。

CI 新增模块清单任务，以及固定版本 Go 官方 govulncheck 检查。数据库不可用会使检查失败，不会被转换成安全通过。本地漏洞数据库两次 TLS 超时，本次漏洞检查未完成。

## 兼容承诺与生态边界

机器可读基线见 [compatibility.json](compatibility.json)，发行边界检查核对工具链、SDK 固定版本、交叉编译目标及必需补丁，防止文档与构建漂移。

历史版本必须先增加固定依赖和完整测试，再进入支持范围；当前不新增历史兼容承诺。第三方 S3 服务需要独立验收对象 API，OtterIO 管理命令不能用于一般 S3 服务。`MC_*` 在 OC 0.x 内继续兼容，移除前至少提前一个次版本公告。

本阶段的生态新增能力是可共享的诊断命令、机器可读兼容清单和可重复的性能/故障验证工具。SDK 版本治理按用户指示暂缓；未配置外部服务时不创建虚假的第三方兼容认证。

仍需独立环境的验证包括分布式拓扑、网关、外部 KMS、通知投递、跨实例复制、历史版本和第三方服务；磁盘耗尽恢复及小时级持续测试也未计入本次通过范围。原有阶段三关于配置往返与真实数据修复的区别继续适用。

## 本地验证记录

最终结果见 [oc-phase-four-results.json](oc-phase-four-results.json)。完整竞态测试、go vet、golangci-lint、发行边界检查、11 个目标交叉编译以及真实服务兼容矩阵的完成状态记录在结果中。测试平台为 Darwin arm64；其他平台的本地运行验证不由交叉编译结果替代。

本次修正的完整兼容矩阵通过 855 项检查；最终二进制另通过包含 30 秒采样的 346 项核心及稳定性检查，详见结果文件内 `reviewFixValidation.finalStabilityRun`（记录各自二进制 SHA-256）。3 项维护回归测试、实际缺失 VCS 构建拒绝、主动触发吞吐失败后的证据保留均通过。检查数随持续采样期间的请求数量变化；SDK 保持不变。二进制清单见 [oc-phase-four.cdx.json](oc-phase-four.cdx.json)，它来自本地开发构建，不是已发布的发行产物。
