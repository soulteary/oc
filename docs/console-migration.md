# OtterIO Web 控制台迁移实施计划

[本机控制台使用指南](zh_CN/console.md) · [English usage](console.md) · [文档目录](zh_CN/README.md)

制定日期：2026-10-08。目标是在 OC 仓库中独立交付 Web 控制台，使 OtterIO 专注存储与管理协议。P1、P2 已完成本机验收，P3 的本机账户与桶配置这一批也已完成验收；**现有 OtterIO 控制台仍保留，默认行为不变**。后续阶段按验收门槛推进，不能用 P1/P2 本机原型的完成替代整项迁移的完成。

## 决策与交付形态

采用同一 OC 仓库中的独立 `oc-console` 可执行程序，复用 OC 的协议规则和别名格式。保留 `oc` CLI 的入口、默认构建与发布方式。第一阶段内嵌纯 HTML/CSS/JavaScript，不引入 Node 构建链；需要组件框架时再根据实际交互复杂度决策。

先支持本机、单操作员、启动时指定一个别名。凭据只存在于进程内，浏览器用短期会话访问本机服务。此形态能较低成本验证 API、权限和交互，不要求先建设身份平台。

集中部署属于另一种产品形态：必须按登录用户建立独立存储身份、凭据和连接池，部署 HTTPS、身份认证、会话撤销与审计。不能把当前本机模式改成监听 `0.0.0.0` 后就当作共享控制台，也不能让多个用户共享进程的管理员别名。本机模式与集中模式的代码可以复用，但部署与信任边界需要分别验收。

## 已确认的收益与成本

收益主要在后续维护：UI 可独立升级和回滚；CLI 与 Web 复用端点、签名、私有 CA 和取消规则；一个控制台可连接不同存储实例；存储服务无需持续维护浏览器登录与静态资源分发。关闭 Web 路由后，存储监听器暴露的浏览器入口减少。

成本包括独立程序的安装和版本组合、外部 API 下的权限差异、额外传输路径，以及集中部署时新增的身份与会话服务。当前 OtterIO 已内嵌前端资源，运行时并不需要 Node；因此移出 UI 不能被表述为“解决服务端 Node 依赖”。资源体积与吞吐改善需要测量，不能只按删除的代码行数推断。

本机代理下载的路径是 S3 → OC → 浏览器，必须控制并发、传播取消并流式转发。以后采用预签名直传需要另行定义公开 S3 地址、TLS 与 CORS，不能把本机可达的内部地址直接发给浏览器。

## 功能与语义迁移清单

1. **桶与对象浏览**：使用 S3 ListBuckets/ListObjectsV2，保留服务端 continuation token 和每页限制。原 Web 允许写权限用户获得空列表等行为，与公开 S3 列举权限并不完全一致；新 UI 必须明确表示禁止列举，不能虚构空目录或用管理员替用户代查。
2. **下载**：初期流式代理、附件下载、特殊 key 原样编码和取消。随后验收 Range、条件请求、版本 ID、SSE、批量 zip、预签名链接及其过期/撤销限制。原 Web 的内部 zip 路径不能直接视为已有 S3 等价接口。
3. **上传**：增加限额、并发与背压、进度、取消和 multipart 清理，只终止本次会话拥有的 upload ID。验证空文件、大文件、网络中断、重试、重复 key 和覆盖确认。
4. **删除**：区分对象、指定版本、delete marker 与前缀递归删除。前缀删除通常需要 ListBucket 加每个对象的 DeleteObject；这是原内部 Web 路径的权限变化。默认不永久删除历史版本，批量操作必须返回部分失败清单。
5. **容量与概览**：先展示当前身份的 AccountInfo 桶容量，接口不可用时降级；不要把管理端全局统计授权给普通用户。桶根目录的 Read/Write 信息不能替代前缀条件的授权判断。
6. **桶策略及共享**：明确 Get/Put/DeleteBucketPolicy 权限，编辑完整策略时处理并发更新与覆盖。公共访问、下载链接与写链接分别说明授权和到期行为。
7. **账户及管理**：普通用户、自身凭据修改、用户/组/策略/服务账号管理分别建模；管理 API 仍以当前用户身份调用。自身改密必须保持账户状态并撤销旧会话，不直接照搬会重新启用账户的通用 AddUser helper。
8. **OIDC/STS**：配置 issuer/client ID/回调与临时凭据刷新、过期和退出。浏览器会话结束与上游临时凭据失效分别处理。按需增加最小公开发现信息，不能为取发现文档恢复整套旧 JSON-RPC。
9. **诊断与流**：日志、trace、通知、profile 和 heal 独立设权限及生命周期。取消订阅必须关闭上游响应体；通知重连没有持久 replay cursor，UI 不宣称补齐断线期间事件。
10. **部署条件**：验证源 IP、SecureTransport、User-Agent、Referer、签名方式和主体类型条件。代理会改变条件上下文，反向代理的转发头需要明确信任名单；前端 HTTPS 不能自动使后端 HTTP 满足 SecureTransport。

## P0：基线与拆分契约

交付：现有功能清单、权限差异记录、架构边界和可回退策略。本计划承接前面的源码评估。

冻结以下边界：`internal/consoleapi` 定义不含凭据的存储操作；`internal/storageclient` 持有签名客户端和连接池；`internal/clienttransport` 共享传输规则；`internal/console` 管理 HTTP 会话；`internal/console/web` 内嵌 UI；`cmd/oc-console` 只负责配置和进程生命周期。不导入 CLI 的 `cmd` 包，不把 CLI 命令直接当成 Web handler。

验收：S3、Admin、浏览器三类身份/协议边界有明确归属；管理员凭据不会成为普通用户授权的替代品。SDK 仍使用当前固定版本，独立 SDK 发布不作为 P1 前置条件。

## P1：本机只读垂直切片（已完成本机验收）

实施顺序：

1. 抽取管理端点校验、独立 CA、签名空请求体与禁止重定向规则，保留 CLI 的流适配行为。
2. 提供每页列举、对象 HEAD/GET 和可选 AccountInfo 的独立客户端；连接池属于实例，不使用 CLI 全局缓存。
3. 实现只读 config v10 加载、明确别名、S3/Admin 地址与 CA 优先级、只允许回环监听。
4. 实现随机登录码、30 分钟会话、登出撤销、Host/Origin/CSRF 校验、输入/并发限制和请求取消。
5. 实现桶选择、前缀导航、真实分页、下载、刷新、错误状态和管理信息降级。
6. 添加独立构建目标、使用文档、协议/会话测试、真实 OtterIO 与浏览器验收。

验收门槛：

- 无登录不能访问存储接口；请求改 Host/Origin、跨站请求、缺失 CSRF 被拒绝。
- 浏览器响应和静态资源不含存储凭据；不在 localStorage 保存登录码/凭据。
- Unicode、空格、`+`、`%` 等 key 原样往返；列表按页请求，下载按字节流转发并验证摘要。
- 请求取消、登出、会话到期与服务关闭能终止上游请求；管理错误不阻塞 S3 浏览。
- 单/双 HTTP 入口与独立 CA 的双 TLS 入口通过真实服务验收；已抽取规则的 CLI 回归通过。
- 默认 CLI 构建与 SDK pin 不变；原 OtterIO Web 继续可用。

本阶段明确不交付上传、删除、共享链接、版本 UI、管理员面板、OIDC、集中部署或发行版附件。可执行原型的使用范围以[使用指南](zh_CN/console.md)及记录的测试结果为准。

## P2：对象写操作与权限一致性（已完成本机验收）

依赖：P1 的会话、取消、分页与传输验收通过。

先完成上传，再完成显式对象删除，最后前缀递归/批量任务。任务状态需要有唯一 ID、当前用户归属、取消与部分失败结果；不能仅靠浏览器页面是否存在决定后台任务生命周期。新增每身份并发、内存和请求体上限，禁止全文件缓冲。

将旧 Web 的所有对象操作作为逐条验收用例：只读、只写、前缀权限、显式 deny、组策略、STS 临时身份、对象锁/保留期、版本桶和 multipart 失败。前缀没有列举权限时禁用递归操作并解释原因，不自动放宽策略。

退出门槛：高风险操作有准确确认范围与失败报告；大文件取消在预算内且清理自身 multipart；下载/上传摘要一致；新旧差异被文档化并接受。先按现有 CLI 兼容预算测量，再依据实际浏览器场景设置独立预算，不能直接宣称复用 CLI 性能结果。

## P3：账户、桶设置和必要管理功能

依赖：对象权限矩阵和错误表示稳定。

按使用优先级实现自身凭据、桶策略/版本/生命周期，再实现用户/组/服务账号和诊断。用服务端权限决定可执行动作，UI 的按钮状态仅作提示。AccountInfo 只返回展示所需字段，默认不把完整 policy 或凭据发给浏览器。

梳理每一项旧 JSON-RPC 是否已有 S3/Admin/STS 对应能力。只有“公开协议无法表达且仍必要”的能力，才在 OtterIO 添加最小、受权限约束且有契约测试的接口；不保留第二套通用浏览器业务协议。服务端变更与 OC 客户端变更分开提交，标明最低版本及降级策略。

退出门槛：明确用户/管理员/临时身份能力；改密后的旧会话处理、策略并发编辑与诊断流取消通过测试；必须保留的旧能力均已覆盖或明确废弃。

## P4：集中部署、发行与兼容支持

是否实施集中模式以真实用户需求决定。需要时单独设计 HTTPS/可信代理、OIDC/STS、每用户身份隔离、凭据储存和轮换、审计、登出与全局撤销、速率限制和安全更新。不得把本机登录码作为多人长期认证方案。

发行任务：在平台矩阵中增加 `oc-console` 归档、校验和、容器与镜像摘要；更新构建清单、许可证/SBOM、来源声明和升级指南。若引入前端依赖，补齐 Go 之外的依赖库存与锁定，不依赖现有 Go 模块 SBOM 自动覆盖 JavaScript。

建立 OC/SDK/OtterIO 的兼容矩阵：当前固定 SDK、当前服务端、最低支持服务端、上个受支持 OC；分别跑本机与集中模式。单/双入口、独立 CA、反向代理、IPv6、S3 key、STS 和权限策略是必测维度。第三方 S3 的对象兼容与 OtterIO 管理兼容分别声明。

退出门槛：目标平台原生执行、真实部署和升级/回滚演练通过；长会话并发和资源回收没有持续增长；安装者可以固定已知可兼容的两个独立版本。

## P5：旧入口弃用与移除

依赖：P2–P4 中承诺支持的功能和部署场景完成，使用者已有可安装的替代版本。

1. 在测试部署使用现有 `OTTERIO_BROWSER=off` 验证 OC 完全独立运行，并保留原二进制及配置回退路径。
2. 发布功能/权限变化清单和安装迁移指南；建议至少经过两个已通知的发布周期收集真实使用反馈，周期长度由发布节奏决定。
3. 再将新部署的 browser 默认值改为关闭；旧部署可以显式开启，保持一个有期限的回退窗口。
4. 最后删除旧静态资源、Web 专用 JSON-RPC、Web 上传/下载/zip 路由、对应测试和过期说明。
5. 审查共享 JWT、`/otterio` 保留路径、Admin、health、metrics、节点通信及日志命令；这些仍可能被其他协议使用，不能按“与 console 名称相关”整块删除。

退出门槛：旧入口关闭时所有受支持场景通过；没有活跃迁移阻塞；旧 UI 专用授权面消失，保留协议与默认数据行为没有回归。删除旧 UI 后的回退是恢复受支持的前一服务端版本，必须提前验证数据/配置向后兼容。

## 执行、验证和回退规则

每一阶段交付可独立审查的代码、运行指南和带版本/平台/二进制摘要的证据。保持客户端、HTTP 会话、UI 和服务端删除四类改动分开评审。优先跑直接相关的测试，再跑受影响 CLI 回归和真实服务；工作流配置存在不代表 CI 已通过。

P1–P4 遇到问题时关闭 `oc-console`，继续使用原 Web 或 CLI；不改存储数据结构。写操作上线后的操作回退与程序回退分别描述，覆盖或永久删除的数据不能用退回旧 UI 恢复。

代码量不等于工期。先记录 P1 实际接入缺陷与验收耗时，再估算 P2/P3；集中模式和 OIDC 作为独立工作包。项目推进的主要门槛是权限语义、身份隔离与部署兼容，不是前端页面数量。
