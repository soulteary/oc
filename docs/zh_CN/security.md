# 安全

[English](../../SECURITY.md) · [文档首页](README.md)

## 私下报告漏洞

本仓库已启用 GitHub 私密漏洞报告。请通过 [报告漏洞](https://github.com/soulteary/oc/security/advisories/new) 提交保密报告，不要将利用细节、凭据、私有入口或受影响客户的数据放入公开 issue 或 PR。

报告应包含 OC 发行版本或源码提交、操作系统与架构、相关入口部署方式、影响，以及使用模拟数据的最小复现。必要时附上检查过的诊断信息或日志。请说明问题发生在客户端、发行包装，还是与 OtterIO 服务端的交互；已知时同时提供服务端版本及使用的补丁。

无法使用 GitHub 私密表单时，可以开一个公开 issue，仅请求维护者提供保密联系方式，不附漏洞细节。维护者提供私密渠道后再发送报告。本文不承诺固定响应时间。

安全测试应限于你有权测试的系统和账号。事故证据保留、已泄露凭据轮换应遵循所在组织的流程。

## 保护凭据和配置

OC 别名可以包含 access key、secret key 和入口设置。本地 `config.json` 不是加密凭据库。Unix 类系统默认目录为 `$HOME/.oc`，Windows 默认使用用户目录下的 `oc`。`--config-dir`、`OC_CONFIG_DIR` 和兼容的 `MC_CONFIG_DIR` 可以覆盖默认位置。

通过操作系统权限保护配置目录、配置备份、会话和分享记录，并防止 CA 信任文件被擅自修改。导入配置会备份原有内容，因此修改或轮换当前凭据不会移除旧备份中的凭据。容器和 CI 应使用受保护的配置挂载或凭据注入，不要将凭据写进镜像或提交到仓库。

`oc alias set ALIAS URL` 和 `oc admin user add ALIAS` 可以交互式询问密钥。交互使用时优先采用提示输入；命令行中的凭据可能出现在 shell 历史和进程列表中。环境变量可以避免字面凭据进入命令参数，但它不是凭据库，有权限的进程、运行器配置或诊断转储仍可能读取它。每项工作流使用独立的最小权限身份，发现可能泄露时及时轮换。

普通别名的文字和 JSON 输出会隐藏 access key、secret key，但并非所有命令结果都已脱敏：

- 服务账号创建的 `--json` 结果包含新 secret key。
- `admin config get` / `export` 和本地健康报告可能包含服务端密钥或敏感环境信息。
- 生成的 Prometheus 配置可能包含 bearer token。
- 分享链接主动携带签名访问参数，在有效期内授予访问权。
- 对象内容、用户名、桶名、对象名，以及服务端 trace / console 记录，即使没有凭据，也可能属于敏感信息。

不要将这些内容放入公开日志，分享前需要检查。当前版本没有 `alias export` 命令；复制 `config.json` 或导出服务端配置同样需要保护密钥。

## 保持 TLS 校验开启

OC 默认验证 HTTPS 证书，对象和管理传输要求 TLS 1.2 或以上。`--insecure` 会关闭本次调用的证书校验，具备网络访问条件的攻击者可能冒充入口。应修正主机名、证书链或 CA 信任，不要把不安全调用保存到生产脚本。

S3 额外 CA 证书放在选定配置目录的 `certs/CAs/`。未显式指定管理 CA 时，管理请求也使用该共享信任池。通过 `--admin-ca`、`OC_ADMIN_CA[_ALIAS]` 或别名配置指定管理 PEM 后，管理信任池改为系统根证书加该 PEM，不再包含额外的 S3 CA；对象入口的信任设置不变。Prometheus 的 `--metrics-ca` 指向 Prometheus 主机上的 S3 入口 CA 文件。

管理地址必须是 HTTP / HTTPS 根地址，不接受凭据、查询参数、片段或路径前缀。管理请求拒绝重定向，避免转发签名请求和加密 IAM / 配置正文。两个监听入口都应优先使用 HTTPS；普通 HTTP 不提供 TLS 传输保密和服务端证书认证。配置方法见 [管理说明](administration.md)。

## 分享前检查诊断信息

`oc --json doctor ALIAS` 使用字段白名单，默认离线，不输出入口主机和路径、凭据、签名或配置目录。`--online` 会额外发起只读服务信息请求，并输出节点数与服务版本。平台和版本信息仍应按组织要求检查后再分享。`certificateVerification` 仅表示客户端校验开关，不能证明证书有效或连接可达。

客户端 HTTP 调试输出会隐藏已知的认证头、会话令牌、Cookie、SSE-C 客户密钥、签名查询参数和 URL 内嵌凭据。这些 HTTP 转储不包含请求和响应正文，敏感重定向头也会脱敏。这只是针对已知字段的保护，不能保证任意日志、错误消息、对象名或服务端输出都适合公开。`--debug`、`admin trace`、`admin console`、健康报告和导出配置仍须检查。

## 从已审核的发行来源安装

使用 [OC GitHub Releases](https://github.com/soulteary/oc/releases) 和 [安装说明](installation.md) 中的镜像仓库。核对时间戳标签、档案 SHA-256 与 `checksums.txt`，并检查 `release-manifest.json` 中的源码提交和产物信息。旧版可能只有程序归档，不能从 Git 标签推定镜像已经存在。发布了镜像的版本，应使用清单 `images` 中记录的镜像地址和摘要。不可变 registry digest 指定确切镜像内容，`latest` 等可变标签可能更新。

校验和、镜像摘要可以相对可信值检测内容变化，但它们不是发行签名，不能独立认证发布者。与产物一起下载的校验和仍依赖发布来源的安全。当前发行工作流没有提供密码学签名验证流程，不应把校验和或 OCI 标签称为已验证签名。发布检查见 [发行说明](releasing.md)。

`oc update` 已禁用，以退出码 1 结束，不查询远程版本、不下载替换程序、不修改当前可执行文件。继承的 MinIO 自动更新检查也已禁用。SUBNET 上传实现已移除；`admin subnet health` 只产生本地输出，并拒绝旧上传参数。升级时按安装说明获取、核对已审核的 OC 发行版。

## 依赖和部署边界

[兼容性基线](compatibility.md) 记录 SDK 固定版本、必需服务端修复和验收范围。服务端 IAM、管理授权、外部 KMS、通知服务和复制配置仍由部署方负责；命令存在不代表这些系统已经验证。

CI 包含 Go 可达漏洞检查和已编译模块清单。它们只为实际运行及对应输入提供证据；漏洞数据库不可用不能算作扫描通过，模块清单也不提供漏洞或许可证结论。持续审核客户端与服务端依赖，并检查所部署版本的对应报告。
