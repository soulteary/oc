# 排查命令失败

[English](../troubleshooting.md) · [配置](configuration.md) · [兼容范围](compatibility.md)

从客户端版本、选中的配置目录和失败操作开始检查。
保留传输输出及退出码；本地文件或远程对象已经存在，不能证明本次传输完成。

## 收集必要的诊断信息

```sh
oc --version
oc --json doctor
oc --json doctor store
```

doctor 默认离线，不请求服务器。成功报告包含客户端、Go、SDK 版本、平台、入口协议、
独立管理地址与 CA 设置，以及是否开启证书校验；不包含入口主机、私有路径、凭据和配置目录。
失败诊断仍应检查后再分享：普通错误记录可能包含本地路径、主机信息和底层错误消息。

已配置的别名可以执行在线检查，管理 ServerInfo 请求的期限为 15 秒：

```sh
oc --json doctor --online store
```

这需要管理查询权限，不验证所有对象操作。在线失败报告错误分类或代码，并返回非零退出码；
离线成功不代表 DNS、网络或证书有效。使用独立配置目录时，所有命令都加上同一个 `--config-dir`。

## 别名或配置与预期不一致

在本机运行 `oc alias list store`，再检查目录选择：
`--config-dir` > `OC_CONFIG_DIR` > `MC_CONFIG_DIR` > 平台默认目录。
`OC_HOST_store` 或 `MC_HOST_store` 会覆盖保存的 S3 设置。
检查变量是否存在时，不要打印其密钥内容；OC 值即使为空，也可能阻止对应 MC 值回退。
取消不需要的覆盖，再运行离线 doctor。

OC 不会自动发现 `.mc`，需要按[迁移指南](migration.md)显式导入版本 10 配置。
初始化报权限错误时，为执行 OC 的账号选择其拥有的可写目录，
不要为了一个任务而放宽全部用户配置的权限。

## TLS 或入口错误

分别检查两个入口：对象操作使用 S3 地址，管理操作使用解析后的管理地址，
可能对应不同主机、端口和证书。核对 DNS、端口、证书主机名、有效期和完整签发链。
私有 S3 CA 放入所选目录的 `certs/CAs/`，管理 CA 使用 `--admin-ca` 或别名配置。

`AdminRedirectDisabled` 表示管理入口发生重定向，应配置实际根地址。
管理请求不支持代理路径前缀或重定向。S3 操作成功而 `admin info`、在线 doctor 失败时，
按顺序检查 `--admin-url`、`OC_ADMIN_URL_<alias>`、`OC_ADMIN_URL`、保存的 `adminURL`。
CA 的独立优先级见[配置指南](configuration.md)。

`--insecure` 会关闭 TLS 证书验证。修复签发链或主机名，不要把这个选项长期保留在定时任务中。

## 认证、权限与不支持的操作

JSON 错误分类可以缩小排查范围：

- `authentication`：检查凭据配对、会话有效期、密钥状态、系统时间，以及代理是否修改签名请求。
- `permission`：检查账号对具体桶、前缀、对象版本或管理操作的策略；列举成功不能证明可写或可管理。
- `not_found`：检查别名、桶、对象拼写和指定的版本。
- `unsupported`：检查部署条件和[兼容说明](compatibility.md)；客户端有命令不代表服务端具备功能。
- `endpoint`、`network`、`timeout`：检查实际地址、代理、DNS、TLS，以及同一时间的服务端日志。
- `watch`、`trace`、`stream`：检查订阅错误，并结合下一节的事件历史限制处理。
- `other`：保留底层消息继续判断，不能据此认定凭据已被接受。

已知 SDK 或服务端错误码会保留在 `error.code` 中，也可能没有这个字段。
普通失败返回 `1`；SIGINT、SIGTERM 通常分别返回 `130`、`143`，清理失败或强制终止可能产生其他非零状态。
除非任务明确处理取消，否则所有非零状态都应按未完成处理。

## 传输、镜像同步与通知

明确重试失败复制，并检查下载内容；旧目标文件不能证明本次成功。
`cp --continue` 创建或恢复复制会话，不保证所有提供商和复制模式都能安全恢复中断操作。

镜像报告覆盖冲突时，先用 `--fake --overwrite` 检查，确认源才是要保留的内容。
预览可能列出删除候选，但实际删除仅在指定 `--remove` 时发生。
`--exclude` 同时影响源和目标比较；时间筛选不会保护仅存在于目标中的对象免于删除。
执行调整后的命令前，重新检查方向和加引号的模式，具体行为见[镜像同步](usage.md#镜像同步目录或前缀)。

`WatchStreamClosed` 表示订阅意外结束；`WatchQueueSaturated`、`WatchEventsLost`
表示本地通知历史可能不完整。独立 `watch`、`find --watch` 返回非零状态，重新订阅不能重放缺失事件。
本地源的 `mirror --watch` 会重新注册并核对当前状态，默认也会定期重扫；深度校验需要显式开启并读取两端。
这些恢复行为不能提供持久化审计历史，也不能代替远程 active-active 复制验收。
需要完整事件历史时，使用持久化的服务端审计系统。

## 提供可以复现的问题

公开 issue 可以包含：

- OC 发布标签、操作系统和架构。
- 服务端版本与部署方式，例如单端口 HTTP 或双端口 TLS。
- 最小命令、相关选项和退出码；用占位符替换密钥、签名 URL、内部主机名和敏感对象名。
- 预期行为、实际行为，以及有帮助的成功 doctor 报告。
- 是否可以在临时本地文件或测试桶上复现。

不要上传 `config.json`、备份、含凭据的导出文件、环境转储、加密密钥、会话令牌、分享 URL，
或未经检查的 `--debug` 输出。JSON 错误也可能包含内部设施信息，发出前检查并脱敏。
疑似漏洞使用[安全说明](security.md)中的私密反馈渠道，不要在普通 issue 中公开凭据或利用方法。
维护者的复现工具见[开发指南](development.md)。
