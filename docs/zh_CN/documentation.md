# 维护 OC 文档

[文档目录](README.md) · [English](../documentation.md)

## 围绕读者的任务组织

根目录 README 负责说明项目用途、安装方式、一次连接示例和后续入口。使用指南分别说明安装、容器、配置、传输、迁移、管理和排错。命令索引用于查找命令，具体参数以所安装版本的 `--help` 为准。贡献、维护与发布步骤单独维护。

组织方式参考了 [GitHub CLI 的 README 与贡献入口](https://github.com/cli/cli)、[rclone 的安装、配置和使用导航](https://rclone.org/docs/)，以及 [restic 按任务编排的手册](https://restic.readthedocs.io/en/stable/)。这些项目提供结构参考；OC 的行为和示例仍须核对自己的源码、命令帮助与测试记录。

## 保持技术事实可核对

- 使用当前构建的 OC 和临时 `--config-dir` 检查 `oc 命令 --help`，避免读取工作区中遗留的旧程序。
- 示例验证使用临时文件或一次性服务端测试实例，不使用已有用户别名、真实凭据或生产桶。
- 区分命令存在、交叉编译成功、CI 覆盖和已有运行验收结果。
- 工具链、SDK、平台与发布信息以 `compatibility.json`、`go.mod` 和发布工作流为准，不套用其他项目的支持承诺。
- 对事件重放、mirror 删除、管理入口优先级和对象锁等有明确限制的行为，链接对应实现或验证记录。
- 保留带日期的报告和哈希。补充当前导航或注明更正背景，不改写历史测试结果。

## 写出可以使用的示例

需要时注明 Shell 和前提条件。归档示例使用真实发布的时间戳标签，并说明如何选择其他版本。容器只有在清单记录了镜像时才使用真实标签，否则采用明确的占位符或本地源码构建示例。地址、路径、账号及凭据占位符应容易辨认，初始配置优先采用交互式凭据输入。

权限要求和破坏性行为放在相关命令旁边，尤其是 `mirror --remove`、删桶、服务控制和配置导入。不要宣传已经禁用的自更新、上游下载渠道、尚不存在的 OC 包管理器配方、没有约定的响应时限或未经验证的服务商兼容性。日志、配置导出和分享链接在进入 issue 前先检查是否包含敏感信息。

## 同步两种语言

英文指南位于 `docs/`，简体中文位于 `docs/zh_CN/`。成对文档的命令、能力、前提和限制应一致，并在页首链接另一种语言。中文以自然、明确的句子解释操作，不逐字套用英文语序。

阶段记录保留原始语言。维护与发布步骤也要同步两种语言。旧指南文件名继续作为导航页保留，让已有链接仍能找到当前说明。

## 检查文档改动

阅读渲染后的 Markdown，检查本地链接、标题锚点、命令和参数，同时核对两种语言的目录和 README 入口。只需重跑受影响的示例；文档检查不等于所有集成场景、平台和服务商都重新通过验收。
