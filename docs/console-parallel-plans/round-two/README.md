原目录 00–09 保留总体设计与首批历史。本目录是当前开发入口，不把协议客户端、撤销 ledger 或诊断 API 再算一遍开发；本轮不沿用首轮 40–70 人日作为剩余工期，也不把并发数直接换算为日历承诺。

## 四个 agent 的排期

协调者也占一个名额时，同时只安排三个开发任务。

1. 第一批：01 真实 CI、02 身份执行器、05 诊断 UI/发现契约；00 冻结接口；第一批 02 独占 server.go/session_clients.go 和原生退休实现并直接接入，00 不同时编辑；第一批诊断 UI 的共享文件由 05 在独占窗口内直接接入，交付后归还 00。
2. 第二批：02 的必要接口稳定后，04 独占认证核心；03a 和 06 开发独立模块。05 的后续发现 API 可在空闲槽继续。
3. 第三批：03b、03c、07 并行；若 04 尚未完成，其继续占一席，其他任务排队。IAM 三项在接口冻结后也可同时认领，但只各改专属文件，由 00 集成公共 dispatcher。
4. 最后：07 对已合并范围执行统一认证；08 在公告和回退门槛满足后执行。

任务顺序是可调整排期。可以提前做协议研究、fixture 与模块，不能在依赖未满足时开放认证/管理动作。07 的矩阵设计和 08 的公告清单可提前准备；完整认证、默认关闭和删除必须按门槛顺序。

## 依赖与冲突控制

02 提供管理撤销/影响范围给 03a/b/c，提供身份/生命周期契约给 04。04/02 给 06 认证与撤销接入点。01/03/04/05/06 的实际结果进入 07，07 和公告窗口共同约束 08。

本轮第一批 `server.go` 和 `session_clients.go` 由 02 在临时独占窗口内直接接入，00 不同时编辑；交付回收后由 00 明确转交 04；UI 通常由 00 排序接入；本轮第一批临时授权 05 独占 app.js/index.html/i18n.js 和专属 DOM 测试，00 在该窗口内不编辑这些文件，交付后窗口回收；go.yml 先归 01；IAM 总 dispatcher 归 00。共享文件同一时刻只有一个负责人。每位 agent 使用独立 worktree，不并行切换同一 checkout。

OIDC issuer/sub 只表示经过验证的独立主体；未知 IAM 父关系保持未知。组策略变更、Deny 移除/恢复和关系竞争必须按真实影响处理；缺原子能力时提交服务端协议需求并保持拒绝。
