# 默认关闭与旧 Web 移除

负责人角色：服务端移除 agent。预计工作量：2–4 人日，不含日历等待。估算含实现、审查、CI 修复与验收，不是日期承诺。

## 启动条件

仅可先研究路由清单；默认值/删除实现依赖 00 范围确认和 08 完整验收，且公告、回退窗口完成。

## 开发内容

- 建立 Web 专用静态资源、JSON-RPC、上传/下载/ZIP 路由与测试的准确删除清单，核对共用认证/JWT、保留路径和节点调用。
- 记录两个已通知的正式发行周期和真实迁移反馈；当前首个公告发行不是两个周期。回退窗口的开始/结束由明确发布决策确定。
- 第一阶段只改变新部署默认 browser 值，保留显式开启和有期限的同版本回退；必须有对应回归和部署说明。
- 回退窗口结束且无活跃阻塞后，第二阶段删除 Web 专用代码及过期说明。
- 保留 S3、Admin、STS、health、metrics、节点通信与共享认证。终端 console 输出/管理员日志流是独立功能，不能按名称一起删除。
- 验证关闭/删除后的真实客户端组合和权限回归；删除后的回退策略需实际版本/data/config 兼容证据。

## 文件和职责边界

拥有：独立 OtterIO 分支中的 Web 专用实现/测试与弃用文档；依照服务端仓库 AGENTS/发布规则执行。

不修改 OC 的身份实现；不在其他工作包未验收时预先删除入口。

## 验收条件

- 默认关闭与删除分成两个 PR/阶段，发布公告和回退要求可追溯。
- 承诺支持的旧 Web 能力已有通过验收的替代或已正式废弃。
- 保留协议与节点认证无回归；客户端配对、数据配置行为和回退路径有证据。
- 发布周期/窗口未完成时只能标记研究就绪，不能宣称移除完成。

## PR 和合并顺序

准确清单与门槛复核 → 默认关闭 PR → 经回退窗口后的删除 PR。

## 认领和交付规则

开始时读取本目录 README 与契约计划，在独立分支和独立 worktree 开发，确认依赖 PR 的实际合并状态。任务文件不是创建、推送或修改其他 agent 分支的授权；按当前用户授权完成本任务的开发和 PR。

只修改本计划拥有的文件。共享文件的改动整理为明确的接入补丁，交给指定拥有者合并；需要提前调整接口时，先更新契约并通知受影响任务，不自行改变已冻结语义。测试使用临时账户和存储，避免实际用户配置或数据。

每个 PR 写明问题、最终行为、验证结果、版本与限制。失败记录与未知结果须保留，不自动重放身份变更，不以管理员代查/代操作普通用户资源。文档和测试证据只声明实际运行过的组合。

交付时提供提交/PR、已完成验收、未解决项和接入要求。共享验收报告、主迁移文档、主前端文件与发布 pin 统一由集成/发行拥有者更新，避免并行覆盖。
