# OIDC 和 STS 协议客户端

负责人角色：OIDC 协议 agent。预计工作量：5–9 人日。估算含实现、审查、CI 修复与验收，不是日期承诺。

## 启动条件

00 固定 issuer/受众/STS 目标及临时凭据契约后可立即开始。

## 开发内容

- 新增隔离的 OIDC 协议模块：服务端固定 issuer/client ID/回调，发现与密钥缓存、state/nonce 生命周期、授权码交换和适用的 PKCE。
- 依据实际 IdP 和 OtterIO STS 支持确定 token 类型、issuer/audience/expiry 等校验责任，并用实际配置验证，不能仅依据浏览器传来的用户信息建立存储身份。
- 通过 STS 换取当前用户临时 S3 凭据，保留 session token 和到期时间；验证会话策略与上游授权交集。
- 明确刷新能力：IdP 不支持刷新、refresh token 轮换或 STS 过期时均需可预测地重新登录，禁止静默换成进程管理员身份。
- 网络、发现、JWKS/令牌交换与 STS 调用有取消/时间界限；重定向、未知 issuer、恶意发现地址、凭据/令牌日志输出受约束。
- 提供给 04 的最小客户端接口、可重复 fixture 和部署配置说明。

## 文件和职责边界

拥有：新增 `internal/oidc` 协议包及测试；新增 STS 适配文件（接口依 00），独立验收脚本/夹具。

不修改 `server.go`、原生认证默认行为、主 UI、公共发行 pin。若现有 SDK 的 STS 调用有缺口，先提出最小独立适配，而非升级全部依赖。

## 验收条件

- callback 注入、state/nonce 错误、code 重放、issuer/受众不符、过期与密钥轮换均有拒绝测试。
- 真实临时凭据可读获准对象，不能越权，session policy 不能扩大权限。
- 刷新成功/不支持/失败、令牌轮换、取消和失联行为可验证，输出不含 token/secret。
- 真实 IdP + OtterIO STS 集成结果保留版本和配置边界。

## PR 和合并顺序

协议客户端 PR → STS/刷新与真实协议验收 PR；04 在首个稳定接口后接入。

## 认领和交付规则

开始时读取本目录 README 与契约计划，在独立分支和独立 worktree 开发，确认依赖 PR 的实际合并状态。任务文件不是创建、推送或修改其他 agent 分支的授权；按当前用户授权完成本任务的开发和 PR。

只修改本计划拥有的文件。共享文件的改动整理为明确的接入补丁，交给指定拥有者合并；需要提前调整接口时，先更新契约并通知受影响任务，不自行改变已冻结语义。测试使用临时账户和存储，避免实际用户配置或数据。

每个 PR 写明问题、最终行为、验证结果、版本与限制。失败记录与未知结果须保留，不自动重放身份变更，不以管理员代查/代操作普通用户资源。文档和测试证据只声明实际运行过的组合。

交付时提供提交/PR、已完成验收、未解决项和接入要求。共享验收报告、主迁移文档、主前端文件与发布 pin 统一由集成/发行拥有者更新，避免并行覆盖。
