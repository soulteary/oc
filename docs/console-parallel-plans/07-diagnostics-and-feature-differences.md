# 诊断流与旧功能差异

负责人角色：诊断 agent。预计工作量：3–5 人日。估算含实现、审查、CI 修复与验收，不是日期承诺。

## 启动条件

00 冻结必须保留范围后可并行；不负责实现所有历史管理功能。

## 本次执行范围修正

实际旧 Web 是 ServerInfo/StorageInfo 快照，没有日志、trace、profile/heal 订阅；这些 CLI 能力不能当作浏览器迁移缺口。本次只实现最小白名单快照与真实权限差异记录。以下通用诊断流设计只在未来明确新增浏览器诊断需求时适用，不作为当前移除门槛。

## 开发内容

- 从旧 Web 与 OC 实际路由形成差异清单；日志、trace、通知、profile/heal 等分别明确浏览器保留、CLI 接替或正式废弃。
- 对必须保留的最小诊断流实现独立后端接口与可取消的流转发；其他能力列出后续工作，不在本估算内暗中扩张。
- 每项操作使用当前主体的服务端权限，限制并发/时长/响应大小；不能以启动管理员身份为普通用户建立诊断订阅。
- 断开、退出、过期和停机关闭上游响应体；重连不宣称回放缺失事件，除非上游提供真实持久 cursor。
- 提供最小 UI 接入补丁与权限提示，由 00 合并；和 05 区分“用户诊断流”与“控制台审计事件”。

## 文件和职责边界

拥有：新增诊断后端、handler、测试与独立验收脚本；本任务差异说明。

主 UI、路由注册、总迁移文档由 00 集成。若保留所有 profile/heal/通知管理能力超过本预算，先重新估算，不自动标记已完成。

## 验收条件

- 管理员可订阅、普通用户/明确 deny 被拒绝；不泄漏跨用户诊断信息。
- 中断、登出、到期、关闭时流和客户端在界限内回收；慢消费者不无界缓冲。
- 实际服务的授权和取消验收；重连/缺失事件说明与能力一致。
- 每个旧能力均有实现/替代/废弃结论；废弃决策经用户确认并进入公告。

## PR 和合并顺序

差异与接口 PR → 最小诊断流 PR → UI/负例与回收验收 PR。

## 认领和交付规则

开始时读取本目录 README 与契约计划，在独立分支和独立 worktree 开发，确认依赖 PR 的实际合并状态。任务文件不是创建、推送或修改其他 agent 分支的授权；按当前用户授权完成本任务的开发和 PR。

只修改本计划拥有的文件。共享文件的改动整理为明确的接入补丁，交给指定拥有者合并；需要提前调整接口时，先更新契约并通知受影响任务，不自行改变已冻结语义。测试使用临时账户和存储，避免实际用户配置或数据。

每个 PR 写明问题、最终行为、验证结果、版本与限制。失败记录与未知结果须保留，不自动重放身份变更，不以管理员代查/代操作普通用户资源。文档和测试证据只声明实际运行过的组合。

交付时提供提交/PR、已完成验收、未解决项和接入要求。共享验收报告、主迁移文档、主前端文件与发布 pin 统一由集成/发行拥有者更新，避免并行覆盖。
