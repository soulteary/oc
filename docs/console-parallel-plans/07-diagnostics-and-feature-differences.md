# 诊断快照与旧功能差异

负责人角色：诊断 agent。原粗估 3–5 人日；按实际范围核实后再估算，包含实现、审查、CI 修复与验收，不是日期承诺。

## 启动条件

00 冻结必须保留范围后可并行；不负责实现所有历史 CLI 管理功能。

## 已核实范围

旧 Web 提供 ServerInfo/StorageInfo 快照，没有日志、trace、profile/heal 订阅。后者属于 CLI 能力，不是此次浏览器迁移缺口。旧普通用户可见的平台、运行时和集群容量，不能由需要 admin:ServerInfo 的管理快照或主体可见桶容量冒充等价实现。

## 开发内容

- 对照旧 Web 与 OC 实际路由形成字段、权限和来源差异清单。
- 实现当前主体签名的最小白名单管理快照，限制并发、时长、响应大小和节点数量，不返回完整上游配置或任意字段。
- 退出、过期和停机取消请求；沿用标准会话租约和原生身份请求前验证。不能用启动管理员身份补足普通用户权限。
- 提供最小 UI 与权限提示的接入补丁，由 00 集成；管理快照和 05 控制台审计分别实现。
- 为旧普通用户缺失的信息提出最小可信服务端发现契约；未知或无权限时保持拒绝，明确记录剩余等价缺口。

## 文件和职责边界

拥有：新增诊断后端、handler、测试、独立验收脚本及本任务差异说明。

主 UI、共享路由注册和总迁移文档由 00 集成。CLI 日志/trace/profile/heal 不在本包新增浏览器功能。

## 验收条件

- 管理员可读取，普通用户与明确 deny 被拒绝；不泄漏跨用户配置或桶信息。
- 登出、到期、关闭时请求和客户端在界限内回收；响应不无界缓冲。
- 实际正式服务授权负例与取消回归均通过，标明浏览器登录及 HTTP/TLS 矩阵范围。
- 普通用户信息差异有明确契约与验收证据；没有实现的字段保持未完成。废弃既有能力必须经用户确认并公告。

## PR 和合并顺序

白名单后端及差异证据 PR → UI/权限提示 PR → 普通用户最小发现契约与等价验收 PR。

## 认领和交付规则

开始时读取本目录 README 与契约计划，在独立分支和独立 worktree 开发，确认依赖 PR 的实际合并状态。任务文件不是创建、推送或修改其他 agent 分支的授权；按当前用户授权完成本任务的开发和 PR。

只修改本计划拥有的文件。共享文件的改动整理为明确的接入补丁，交给指定拥有者合并；需要提前调整接口时，先更新契约并通知受影响任务，不自行改变已冻结语义。测试使用临时账户和存储，避免实际用户配置或数据。

每个 PR 写明问题、最终行为、验证结果、版本与限制。失败记录与未知结果须保留，不自动重放身份变更，不以管理员代查/代操作普通用户资源。文档和测试证据只声明实际运行过的组合。

交付时提供提交/PR、已完成验收、未解决项和接入要求。共享验收报告、主迁移文档、主前端文件与发布 pin 统一由集成/发行拥有者更新，避免并行覆盖。
