# 集中部署 审计与稳定性

负责人角色：部署保障 agent。预计工作量：8–14 人日。估算含实现、审查、CI 修复与验收，不是日期承诺。

## 启动条件

00 契约后可先做部署与审计模块；会话接入依赖 04，撤销接入依赖 01。

## 开发内容

- 固定单实例集中部署基线：直接 HTTPS 或明确可信代理模型、固定外部 URL/CA、配置与敏感材料读取、启动校验、重启和回退说明。
- 当前原生模式不能直接信任转发头。若支持反向代理，定义受信任 hop/地址、Host/Origin 和协议推导，并验证伪造头无法绕过。
- 增加可接入的认证/管理审计事件，记录主体、准确目标、动作、结果与关联信息；不记录 token、secret 或敏感原始请求。审计不能变成跨用户信息泄漏。
- 区分请求前验证、空闲/在途主动检测与 IdP/服务端撤销；只实现可验证的检测频率与故障策略，不宣称即时跨实例撤销。
- 登录/刷新/校验限流、长期连接/任务配额、客户端回收与资源观测；覆盖多用户负载、上游失联和进程退出。
- 运行长期稳定性、重启与故障恢复验收。多实例共享会话/撤销另立扩展计划，预计额外 5–10 人日，不混入基线。

## 文件和职责边界

拥有：新审计/运行保障模块及测试、独立部署示例和任务文档、专属压力/稳定性验收脚本。

启动和会话接入补丁交 04/00；现有发行 Compose pin 与总兼容矩阵由 08 更新。不得覆盖 IAM/OIDC 共用认证核心。

## 验收条件

- 普通用户不可读他人审计/任务；敏感信息不进入日志和偏好文件。
- 代理伪造、限流、到期、故障、取消和恢复有明确测试。
- 报告写出负载、时间、内存/连接/客户端数，验证回收后的趋势；不能用短测代表长期稳定。
- 同版本重启/配置回退可演练，OIDC 和原生模式的支持边界清楚。

## PR 和合并顺序

部署契约/校验 PR → 审计与限流 PR → 外部变化和稳定性验收 PR。

## 认领和交付规则

开始时读取本目录 README 与契约计划，在独立分支和独立 worktree 开发，确认依赖 PR 的实际合并状态。任务文件不是创建、推送或修改其他 agent 分支的授权；按当前用户授权完成本任务的开发和 PR。

只修改本计划拥有的文件。共享文件的改动整理为明确的接入补丁，交给指定拥有者合并；需要提前调整接口时，先更新契约并通知受影响任务，不自行改变已冻结语义。测试使用临时账户和存储，避免实际用户配置或数据。

每个 PR 写明问题、最终行为、验证结果、版本与限制。失败记录与未知结果须保留，不自动重放身份变更，不以管理员代查/代操作普通用户资源。文档和测试证据只声明实际运行过的组合。

交付时提供提交/PR、已完成验收、未解决项和接入要求。共享验收报告、主迁移文档、主前端文件与发布 pin 统一由集成/发行拥有者更新，避免并行覆盖。
