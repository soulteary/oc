# OIDC 控制台登录与临时会话

负责人角色：OIDC 会话 agent。预计工作量：5–9 人日。估算含实现、审查、CI 修复与验收，不是日期承诺。

## 启动条件

依赖 01 身份生命周期与 03 客户端；必须取得核心会话文件独占接入窗口。

## 开发内容

- 接入独立认证模式、登录跳转/回调与错误状态，保持本机和原生 IAM 的行为及默认值。
- 每个用户保有独立 STS 凭据、客户端、身份与偏好作用域；禁止 OIDC 会话借用启动 alias。
- 定义浏览器会话期限与 STS/IdP 到期关系；并发刷新只执行一次，安全替换客户端并保留在途租约，失败不延长旧凭据权威。
- 登出撤销 OC 会话、取消拥有任务、清除敏感表单；明确浏览器登出、IdP 登出与上游 STS 失效的不同语义。
- 刷新、登出、到期、权限变化与回调并发时，过期登录/旧 refresh 结果不能重新提交或复活会话。
- UI 接入由 00 合并；无需向浏览器暴露 S3 secret/session token/refresh token。

## 文件和职责边界

拥有：新增 OIDC HTTP 处理文件/测试、会话刷新实现、`cmd/oc-console` 的 OIDC 配置文件。核心 `server.go` 与 `session_clients.go` 在接入窗口临时转交本任务。

不修改 03 的 token 校验规则，不自行改变 01 的撤销映射，不编辑发布工作流。

## 验收条件

- 两个真实 OIDC 用户对象权限、会话、任务和偏好隔离；自身退出不影响另一用户。
- Secure/HttpOnly cookie、Host/Origin/CSRF、回调重放和固定端点校验通过。
- 临时凭据到期、刷新竞争、停止进程、过期回调与客户端清理 race 测试。
- 单/双 HTTPS 存储入口、独立 CA、真实 IdP 和负权限案例验收。

## PR 和合并顺序

登录/回调 PR → 临时客户端与刷新 PR → UI 和端到端验收 PR。

## 认领和交付规则

开始时读取本目录 README 与契约计划，在独立分支和独立 worktree 开发，确认依赖 PR 的实际合并状态。任务文件不是创建、推送或修改其他 agent 分支的授权；按当前用户授权完成本任务的开发和 PR。

只修改本计划拥有的文件。共享文件的改动整理为明确的接入补丁，交给指定拥有者合并；需要提前调整接口时，先更新契约并通知受影响任务，不自行改变已冻结语义。测试使用临时账户和存储，避免实际用户配置或数据。

每个 PR 写明问题、最终行为、验证结果、版本与限制。失败记录与未知结果须保留，不自动重放身份变更，不以管理员代查/代操作普通用户资源。文档和测试证据只声明实际运行过的组合。

交付时提供提交/PR、已完成验收、未解决项和接入要求。共享验收报告、主迁移文档、主前端文件与发布 pin 统一由集成/发行拥有者更新，避免并行覆盖。
