# Range 和条件下载

负责人角色：下载协议 agent。预计工作量：3–5 人日。估算含实现、审查、CI 修复与验收，不是日期承诺。

## 启动条件

00 固定下载接口后可并行实现后端；HTTP 注册交 00 集成。

## 开发内容

- 补浏览器下载的单 Range 与条件请求契约，明确多 Range 是实现还是拒绝；优先不承诺 multipart/byteranges。
- 保留普通/历史版本/null version、ETag 条件、Unicode key 和权限差异；Range 不可绕过选中版本授权。
- 正确处理 206、416、Content-Range、Content-Length、HEAD 和适用的条件状态；上游不支持时不能把完整对象误报为部分响应。
- 流式传输、背压、读取/写入取消与客户端租约保持原有预算，不全文件缓冲。
- 不改变 ZIP 的对象字节语义或通过 Range 意外开放历史版本写入。

## 文件和职责边界

拥有：新增 Range 后端/适配文件、独立下载 handler 文件及测试、专属真实验收脚本。公共接口由 00 合并；`server.go` 原有下载入口的替换由 00 接入。

不并行编辑原生会话文件或主 IAM/OIDC UI。

## 验收条件

- 起止、后缀、越界、空对象、截断、条件不符、历史版本和缺失权限均有测试。
- 真实单/双 HTTP/TLS、独立 CA 与被拒绝版本的负例。
- 摘要/字节范围正确，取消与内存不回归，普通下载/ZIP 回归通过。

## PR 和合并顺序

后端与协议 PR → handler 接入与真实验收 PR。

## 认领和交付规则

开始时读取本目录 README 与契约计划，在独立分支和独立 worktree 开发，确认依赖 PR 的实际合并状态。任务文件不是创建、推送或修改其他 agent 分支的授权；按当前用户授权完成本任务的开发和 PR。

只修改本计划拥有的文件。共享文件的改动整理为明确的接入补丁，交给指定拥有者合并；需要提前调整接口时，先更新契约并通知受影响任务，不自行改变已冻结语义。测试使用临时账户和存储，避免实际用户配置或数据。

每个 PR 写明问题、最终行为、验证结果、版本与限制。失败记录与未知结果须保留，不自动重放身份变更，不以管理员代查/代操作普通用户资源。文档和测试证据只声明实际运行过的组合。

交付时提供提交/PR、已完成验收、未解决项和接入要求。共享验收报告、主迁移文档、主前端文件与发布 pin 统一由集成/发行拥有者更新，避免并行覆盖。
