# 共享契约与集成协调

负责人角色：集成协调者。预计工作量：计入各工作包，不另加开发估算。估算含实现、审查、CI 修复与验收，不是日期承诺。

## 启动条件

所有工作包的共享接口和最终合并顺序；可立即开始。

## 开发内容

- 冻结旧 Web 能力清单，逐条标明必须保留、CLI 接替或正式废弃；原生 IAM、OIDC/STS 和单实例集中部署是当前完整替代基线。多实例、目录登录等新增范围单独评估。
- 记录原生 IAM 当前主分支能力与 PR #32 用户删除的状态。未合并不能作为主分支事实；依赖它的代码应等合并或明确建立依赖分支。
- 与 01、03、04、05、06、07 确认最小接口：服务器可信的主体/父身份、会话到期、临时凭据版本、客户端替换与回收、影响范围、请求取消、审计事件、Range 和有界 ServerInfo/StorageInfo 诊断快照。
- 将接口提案作为契约 PR；最终 Go 类型由指定文件拥有者落地。字段和值来自可验证上游身份，不能直接信任浏览器提供的目标/主体信息。
- 契约明确成功、明确拒绝、结果未知三种处理；会话撤销必须覆盖尚未提交的登录、请求租约和拥有的任务。组/策略影响范围无法权威确定时先拒绝操作，不猜测为空或扩大为全局停机。
- 集成协调者统一接入 HTTP 路由和 UI，并维护共享前端行为测试。04 接入登录时获得核心会话文件的独占接入窗口，01 暂停同文件修改。
- 每轮合并后运行相关回归，再由 08 执行统一真实版本矩阵；任何能力缺失保持拒绝/明确降级。

## 文件和职责边界

拥有：本目录 README、契约说明、`internal/consoleapi` 的跨工作包公共定义、`internal/console/web/app.js`、`index.html`、`i18n.js`、共享 `buildscripts/test-console-web.js` 与 `test-console-integration.py`、总迁移文档。

`internal/console/server.go`、`session_clients.go` 的身份变化窗口先交 01，随后交 04；Range/诊断路由的最终注册由协调者执行。不得让三个 agent 同时编辑核心路由。

## 验收条件

- 所有任务能仅凭任务文件和契约说明开始工作，依赖顺序无环。
- 每个共享文件只有一个当前拥有者，接口变更有版本/兼容说明。
- 全部必须保留能力具备对应验收项；缩小支持范围要取得用户决策并进入正式公告，不能由某个工作包静默决定。

## PR 和合并顺序

契约先行；01 → 02，03 + 01 → 04，04 → 05 的会话接入；06/07 后端独立并行。08 先建立基线，最后收集全部集成产物。09 最后启动。

## 认领和交付规则

开始时读取本目录 README 与契约计划，在独立分支和独立 worktree 开发，确认依赖 PR 的实际合并状态。任务文件不是创建、推送或修改其他 agent 分支的授权；按当前用户授权完成本任务的开发和 PR。

只修改本计划拥有的文件。共享文件的改动整理为明确的接入补丁，交给指定拥有者合并；需要提前调整接口时，先更新契约并通知受影响任务，不自行改变已冻结语义。测试使用临时账户和存储，避免实际用户配置或数据。

每个 PR 写明问题、最终行为、验证结果、版本与限制。失败记录与未知结果须保留，不自动重放身份变更，不以管理员代查/代操作普通用户资源。文档和测试证据只声明实际运行过的组合。

交付时提供提交/PR、已完成验收、未解决项和接入要求。共享验收报告、主迁移文档、主前端文件与发布 pin 统一由集成/发行拥有者更新，避免并行覆盖。
