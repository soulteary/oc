# 02 身份关系与服务端协议

第一阶段可开始；复用已有原生撤销执行器，不重写 ledger。先调查实际 OtterIO 源码/发行能力，列明条件创建、绑定、改密、关系与临时身份的缺口。

交付顺序：主体/关系/影响契约 → 最小权威关系接口 → 必需的原子 IAM 修改协议 → OC 适配及能力探测。每个服务端协议在 OtterIO 独立 worktree/PR 实施，记录最低能力版本；不在 OC 中通过管理员代查或预读消除授权竞争。

关系必须区分未知、已知空、快照过期和 revision 冲突。确认成功/未知结果按权威影响集合撤销；明确拒绝保留会话。OIDC issuer/sub 不能推导 native 父用户；未知映射不妨碍独立登录，但相关管理操作保持拒绝。

验收覆盖父/子、组成员、Allow/Deny 交错、关系与修改竞争、并发登录、重建相同用户名、revision 冲突、无权限、失联和缺协议。测试服务端原子保证及 OC 的拒绝/退休行为，保留 S3/Admin/STS 正常行为。

独占身份专属模块和服务端专属协议文件；现有 Console 核心与共享 IAM 文件由 00 接入。交付协议契约、能力表、源码/真实程序身份和旧版本安全降级；发行是否包含协议由 05 另行认证。
