# 03 IAM 三项并行任务

后端调查/fixture 可提前开始；开放动作依赖 02 原子协议与影响集合、00 公共类型冻结。现有创建/启停/删除能力保留，不重复开发。每个子任务独立认领、worktree、文件和提交。

## 03-user 用户

管理员安全改密、条件策略绑定；保持账户启停状态，不使用会重新激活账户的通用 helper。自身和他人修改通过影响执行器；新凭据只确认成功后显示一次，失联不回显未知凭据、不重试。细项参考 [原任务](../round-two/03a-iam-users.md)。

## 03-group 组

成员增删、启停、删除、条件策略绑定；真实分析 Allow/Deny 的影响，原子覆盖成员/策略竞争。恢复权限不能恢复旧 cookie。细项参考 [原任务](../round-two/03b-iam-groups.md)。

## 03-service-account 服务账号

启停、改密、限制策略和删除；验证权威父关系与限制策略交集，不允许扩权、不猜测父身份。细项参考 [原任务](../round-two/03c-iam-service-accounts.md)。

## 共同交付条件

每项先后端/协议负例，再撤销/生命周期，再 UI。独占新增专属模块和验收脚本；共享 iam.go、consoleapi、capabilities、主 UI 交 00 顺序接入。不能仅因为启用 allow-writes 就开放未验证管理动作。

覆盖管理员/普通用户/explicit deny、默认只读、CSRF、缺能力、revision 冲突、未知关系、确认/拒绝/失联、自身与无关用户隔离；真实单/双 HTTPS 与独立 CA。native/OIDC/STS/服务身份按服务端支持范围单独断言，不能给 OIDC 管理动作补管理员凭据。
