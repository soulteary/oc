# 原生 IAM 管理能力补全

负责人角色：IAM 管理 agent。预计工作量：5–9 人日。估算含实现、审查、CI 修复与验收，不是日期承诺。

## 启动条件

依赖 01 撤销执行器；后端研究、协议差异与测试夹具可提前并行。

## 开发内容

- 补普通用户管理员改密与条件策略绑定；不能用重新启用账户的 helper 替代安全改密。
- 补组成员增删、状态、删除与条件组策略绑定。启用/停用组可能恢复或移除 Allow/Deny，须按真实影响主体处理，不能按动作名称判断“仅增权”。
- 补服务账号启停、改密、限制策略与删除；区分服务账号自身、父用户、相关临时身份，保留服务端 root/目录/STS 限制。
- 现有条件创建、轮换和绑定协议按版本能力验证；缺失时拒绝。绑定编辑保留 revision/冲突语义，禁止最后写入覆盖并发配置。
- 读取权威关系再准备变更，并说明并发关系变化能否由服务端原子协议覆盖；否则拒绝不安全动作或先提交服务端协议 PR。
- 后端每次以当前会话身份调用；新凭据只返回一次，已有/调用者输入的密钥不回显，未知结果不返回未经确认的密钥。
- 提供 UI 动作、确认范围与结果提示的接入补丁，由 00 合并，不直接放开所有原生动作白名单。

## 文件和职责边界

拥有：`internal/storageclient/iam.go`、新增 IAM 后端辅助文件/测试、`internal/console/iam.go` 和任务专属 HTTP 测试。公共类型由 00 合并；会话执行器由 01 拥有。

真实验收新增 `buildscripts/console_iam_management_acceptance.py`，不并行改共享 native 验收入口。需要 OtterIO 改动时另开服务端分支/PR并声明最低版本，不以 OC 补丁冒充已发布能力。

## 验收条件

- 普通用户、管理员、明确 deny、父/子身份的权限正负例。
- 未知关系、条件冲突、服务端不支持、失联和重复提交均安全处理。
- 组成员/策略更改影响的会话被准确撤销，未影响用户仍可用；旧会话不能因后续恢复权限而复活。
- 单/双 TLS 的真实服务验收；默认只读、CSRF、准确目标确认与本机模式回归通过。

## PR 和合并顺序

按用户改密/绑定、组管理、服务账号管理分成 3–4 个可独立审查 PR；每个完成后再开放其 UI 动作。

## 认领和交付规则

开始时读取本目录 README 与契约计划，在独立分支和独立 worktree 开发，确认依赖 PR 的实际合并状态。任务文件不是创建、推送或修改其他 agent 分支的授权；按当前用户授权完成本任务的开发和 PR。

只修改本计划拥有的文件。共享文件的改动整理为明确的接入补丁，交给指定拥有者合并；需要提前调整接口时，先更新契约并通知受影响任务，不自行改变已冻结语义。测试使用临时账户和存储，避免实际用户配置或数据。

每个 PR 写明问题、最终行为、验证结果、版本与限制。失败记录与未知结果须保留，不自动重放身份变更，不以管理员代查/代操作普通用户资源。文档和测试证据只声明实际运行过的组合。

交付时提供提交/PR、已完成验收、未解决项和接入要求。共享验收报告、主迁移文档、主前端文件与发布 pin 统一由集成/发行拥有者更新，避免并行覆盖。
