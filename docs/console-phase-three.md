日期：2026-10-08（本地时区）；结果使用 UTC。**P3 的本机桶设置与自身账户这一批已完成实现、修正和验收**。本次承接更新后的 OC、OtterIO 和独立 SDK，交付桶策略、版本配置、生命周期和原生 IAM 自身改密。用户、组、服务账号管理和诊断仍是 P3 后续任务；集中部署、发行与旧 Web 移除仍按 P4–P5 门槛推进。

## 实现与版本边界

控制台沿用本机回环监听、单操作员、启动时固定一个别名的形态。配置读取可在默认只读模式使用；配置修改和自身改密还需进程显式带 `--allow-writes`，通过登录、准确 Origin、CSRF 和操作确认。桶列举与桶设置权限独立，无法列举桶时可以手填准确桶名。

新增功能没有修改 `go.mod`、`go.sum`，也没有修改独立 SDK、CLI 默认构建或 OtterIO browser 默认值。当前固定服务端为 `6f6d0835ddff68020f1491c403b958fade22841f`，存储 SDK 为 `github.com/soulteary/otterio-sdk/v7 v7.3.1`。**固定服务端尚未包含本次 P3 协议**：保护性配置写入和自身改密需要构建本次 OtterIO 源码，或在固定源码副本应用 [P3 补丁](../buildscripts/console-server-p3.patch)。OC 没有通过本地 module replace 隐式取得相邻源码。

未升级服务端时，控制台仍能读取已有 S3 桶配置；无法发现自身接口时显示 unknown，保护性写入明确返回不支持。它不会去掉条件头后重试写入，也不会借用 root 身份代查或改密。

## 完整文档与并发保护

策略使用 JSON；版本和生命周期使用 XML。读取返回完整文档、存在状态和不透明 revision。未保存的草稿在读取替换前需单独确认，取消或读取失败保留原内容。保存前展示准确桶名、类型、完整内容和风险，删除只开放策略与生命周期，版本配置不能用删除表达。

存储使用 S3 原有资源和方法，新能力通过 `X-Otterio-Bucket-Config: v1` 宣告。读取返回 `X-Otterio-Config-Revision` 和 `X-Otterio-Config-Exists`，写入将 `X-Otterio-Config-If-Match` 纳入 V4 签名。服务端在桶元数据事务锁内读取持久化配置、比较 revision、保存并取得提交后的 revision；同时保护普通元数据更新、缓存载入、迁移及桶创建/删除，避免同一元数据文件内其他配置被覆盖。释放事务锁后再等待有期限的节点通知，避免通知端尝试相同锁时相互等待。

revision 是“类型 + 原始持久化内容”的 SHA-256，不是单调递增版本号。恢复相同内容、删除后再次回到无配置状态，可得到先前相同的 revision；这项保证检测当前内容不同，不能检测内容相同的中间变更。

服务端成功响应携带实际提交状态；OC 随后重新读取持久化文档并检查 revision 一致，显示存储规范化后的实际值。提交后有其他编辑则显示冲突；提交成功但无法完成读回则显示结果不确定，保留草稿并要求重新读取。修改请求只发送一次，不自动重放；读取操作仍可使用 SDK 的读取规则。

服务端仅接受实际支持的字段。条件写路径拒绝重复/未知 JSON 字段、未实现的 XML 字段、重复标量、多根文档、尾随数据及 DTD；版本配置只支持 Status，MFADelete、排除前缀等未实现能力不会被默默丢弃。生命周期空标签名会导致原解析器在规范化时移除标签、扩大匹配范围，现在在保存前拒绝。所有生命周期动作现统一经过前缀和标签过滤；匹配按对象实际的 URL 编码标签解码，避免非当前动作绕过标签、重复入选及共享切片竞争。仅删除过期标记的规则也会被正确扫描。保护写路径还拒绝 Tag 与 ExpiredObjectDeleteMarker=true 的组合。

**后续实现已开放 erasure 的 `NoncurrentVersionTransition`**，并完成持久化目标、完整执行、指定版本恢复及删除保护，详见[转换与恢复记录](lifecycle-transition.md)。条件写入只接受已实现的 `NoncurrentDays`、`StorageClass`；`NewerNoncurrentVersions` 仍拒绝。完整文档不代表存储可以保留未知扩展字段或原始格式。

控制台输入文档最多 1 MiB，服务端另按类型施加原有上限；两端拒绝非法 UTF-8 和孤立 UTF-16 转义，避免 JSON 解码将秘密值或策略静默换成 U+FFFD。服务端验证完整请求体 SHA-256/MD5，从收到配置请求头起限制读取期限，覆盖 Fiber 进入处理函数前的预读；没有 V4 签名的条件头不能获得保护性写语义。能力仅在受支持的 FS 和单 pool erasure 路径开放；gateway、多 pool 及未知实现不宣告保证。真实集群并发尚未验收。

## 自身账户与改密

新增最小管理接口 `/otterio/admin/v3/self-credentials`。GET 只返回自身类别、状态和是否可改密，不返回 access key、secret、session token 或 IAM policy。PUT 使用当前别名签名和 madmin 加密请求，只接受新 secret，不接受目标用户或状态字段。

仅本机原生、enabled 的普通 IAM 账户可改密；root、STS、服务账号、目录身份、disabled 用户、分布式模式、etcd 和 OPA 模式拒绝此功能。身份类别和按钮状态只作提示，提交时会在 IAM 锁内重新检查身份、当前 secret、状态和用户/组显式 deny。只更新 secret，保持账户状态、组及策略，避免通用 AddUser 路径重新启用账户。新值为 8–128 个 UTF-8 字节，拒绝 NUL、CR 和 LF。

改密暂停期间注销仍经过 Origin、身份和 CSRF 检查，并撤销该浏览器会话；读取中的登录请求在创建会话时重新检查暂停状态，防止创建即将失效的会话。OC 改密前必须取得全部写操作槽位，活动上传、删除、配置写入及清理期间返回 busy。确认成功后，响应先发出，再撤销该 OC 进程的全部浏览器会话和任务，关闭监听与连接池。若提交后的传输、确认或节点传播结果不明确，也停止旧连接，要求从终端核实账户后重新启动。已知写入前的权限、能力或发现失败会保留会话，并明确表示无需重启。

浏览器提交、取消、退出和离开页面会清除输入；不会保存在 localStorage。OC 不自动改写本地别名，终端提示更新别名并重新启动，页面提示重新加载并使用新的登录码。旧 IAM secret 的拒绝与 OC 会话关闭分别验证；这里不承诺撤销其他进程、已有 STS 或服务账号凭据。

## 接入中发现并修正的问题

保留中间失败证据，避免将失败记录覆盖为通过：

- [提交确认缺失](console-phase-three-intermediate.json)：最初 S3 保存响应没有宣告提交 revision，客户端不能确认结果。现改为从同一次事务的实际提交内容生成确认头，并读回核验。
- [旧服务发现差异](console-phase-three-legacy-intermediate.json)：固定服务端对未知管理路径返回 400/InvalidRequest，而非 404。现以能力标识和有界响应判定旧服务，安全返回 unknown，同时保留实际授权错误。
- [生命周期匹配范围扩大](console-phase-three-filter-intermediate.json)：空 Tag.Key 原先被规范化为无标签 Filter，可能匹配所有对象。新增保存前验证和真实 HTTP 拒绝测试，拒绝后 revision 保持不变。

另外修正了元数据缓存载入与迁移参与事务的问题、节点通知持锁等待、删除桶后产生孤立配置、body 未读完导致摘要不验证、IAM 并发禁用/deny/secret 变化、改密确认发出前关闭以及已知失败误报结果不确定。定向回归分别覆盖这些边界。

## 本轮独立复查与修正

[复查原始证据](console-phase-three-audit-results.json)保留修正前失败、最终定向结果及上一轮构建记录。本轮按客户端、HTTP、前端、服务端交叉复查，逐项修正后再次检查：

- 草稿读取会直接丢弃编辑、失败读取无法恢复；增加替换确认并保留失败前的文档、revision 和准确保存范围。
- 畸形确认、重定向、重复协议头、202 或非空成功响应可能被误信；确认现在要求唯一且一致的状态、空 200/204，以及保存后的实际读回。提交后不可信错误或重定向按未知结果处理。
- 自身类别重复字段及大小写别名可能误提示可改密；严格检查最小 DTO。401/403 在读取错误体前处理，防止大体或停发掩盖权限失败；S3v2 连接只读。
- 非法 Unicode 曾在解码时被替换后发给存储；入口、直接客户端和服务端按相应层拒绝，合法成对转义及显式 U+FFFD 保留。
- 改密暂停阻止注销，以及在途登录绕过暂停；补齐注销校验与会话创建时的锁内检查，覆盖发起者、其他会话及写槽位。
- 生命周期标签绕过、重复动作、共享切片竞争、编码标签与标记扫描遗漏；修正实际引擎；原复查阶段拒绝尚未完成的非当前转换，后续已实现并另行验收。
- 配置预读未受到处理函数内期限保护；把期限接入实际服务器收到请求头的位置，并验证停发、提前拒绝及连接复用。
- 旧配置清理失败仍允许后续确认，以及复制与版本暂停竞争；迁移清理失败阻止后续提交，复制的版本依赖在同一持久化事务内重新检查。

原复查阶段将非当前转换列为后续工作，没有合入仅按 IsLatest 选择目标的实验性修正。后续实现改为持久化准确目标与版本，原记录及反例保留，当前结果见[新的验证记录](lifecycle-transition-verification.json)。

## 验证与重现

以下 P3 报告属于原 30 文件补丁（SHA-256 `04e8553175d0de9fb448f2167d33d48e45d03407f57335dce2b939d969b30001`）的历史验收，保留原始输出；当前补丁包含后续运行时实现，必须以[新的验证记录](lifecycle-transition-verification.json)及其中的二进制摘要为准。

[最终检查汇总](console-phase-three-verification.json)记录平台、固定版本、实际二进制、30 文件补丁等价检查、通过项及未执行项。同一个最终控制台构建完成以下真实服务验收，四场景均为 `single-http`、`dual-http`、`single-tls`、独立 CA 的 `dual-tls`：

- [P3 新协议](console-phase-three-results.json)：固定源码加本次补丁，每场景 20 组，共 80 组。覆盖三种配置的读取、规范化文档读回、冲突及零写入拒绝、无列桶权限的组身份、显式 deny、真实 STS 和自身改密。四场景改密确认至正常退出为 0.033–0.052 秒，旧 secret 拒绝，新 secret 保持 enabled 和组权限，本地 alias 不变。
- [未升级服务端降级](console-phase-three-legacy-results.json)：固定源码无 P3 补丁，每场景 11 组，共 44 组；配置可读，未知自身信息及无保护写入/改密被明确限制。

性能遵循用户更新后已有的固定五组配对测量：交替 CLI→控制台、控制台→CLI，记录全部原始耗时与每次 65 MiB 内容摘要，以配对比值中位数判断，不取最好一次，不增加样本后重新选结果。四场景控制台上传 342.2–378.7 MiB/s；配对比值中位数 67.9%–74.3%，均高于原 50% 门槛。采样峰值 RSS 99.7–112.5 MiB，取消 0.052–0.057 秒，活动写关闭 0.008–0.009 秒；原 5 MiB/s、512 MiB、120 秒传输与 5 秒取消预算均未放宽。本机短时测量不代表生产吞吐或长期稳定性，0.1 秒 RSS 采样可能遗漏瞬时峰值。

## 后续任务与回退

非当前远端转换、恢复与目标保护已完成本机实现与验收。下一批为用户/组/策略/服务账号管理、日志/trace/通知等诊断流，然后完成发行和目标平台原生执行。OIDC、多人独立身份与共享部署需要单独实现；还未提供历史版本管理、Range、ZIP 或预签名共享。

服务端协议尚未发布并被 OC pin：应先分别审查并提交两个仓库变更、发布服务端，再更新固定版本和兼容矩阵；不能把可应用补丁当作发布完成。完成剩余功能、迁移说明及回退演练后，才能推进旧 Web 默认关闭和删除。

遇到问题可停止 OC，使用原 Web 或 CLI；软件回退不会撤销已经保存的策略、版本状态、生命周期或 secret，需要单独核实和恢复配置。旧 UI 继续保留，本阶段没有删除其资源或专用路由。
