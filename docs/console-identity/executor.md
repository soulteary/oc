# 原生身份变更执行器

原生改密、用户禁用和删除使用同一个 `identityMutation` 生命周期。影响集合由 OC 已验证的原生连接 principal 或服务端支持的直接 IAM 用户目标建立，不接收浏览器提供的主体关系。未知、空、包含无效主体的影响集合在预留写入资源之前拒绝。

执行器在同一服务器锁内预留所有写槽并安装目标登录/请求屏障。活动写入（含 multipart 清理）导致预留回滚；其它用户的读取和登录仍可继续。明确拒绝释放屏障并保留会话；成功或结果未知使准确目标的会话退休。删除不存在的用户仍退休旧 cookie，防止同名重建复活。自身变更在响应尝试之后退休，即便连接已经断开。既有登录 epoch 和墓碑回收继续阻止变更前启动的登录提交。

本次不新增父/子或组成员身份索引。当前 `GetUserInfo`、`GetServiceAccountInfo`、`GetGroupDescription` 等独立读取不能证明一个随后提交的关系修改影响集合。它们可能提供显示信息，但不能作为原子撤销授权契约。现有禁止相关修改的限制继续有效。

后续服务端协议必须至少提供：

- 来自权威服务端的、带作用域及版本的主体/父子/组关系；明确区分已知空、未知和过期。
- 身份修改原子校验该版本；关系已改变时拒绝，并且不得已经提交修改。
- 在确认响应中给出此次实际影响的权威主体集合；结果失联时 OC 有足够的预先权威范围安全退休，禁止自动重放。
- 多个 OC 实例需要服务端撤销世代或主动检测协议；本地 executor 不提供跨实例撤销。

OIDC 的已验证 issuer/subject 使用独立身份命名空间，不等于 IAM access key。STS 响应尚未提供权威父关系时，该关系保持未知；独立 OIDC 登录可继续，但依赖父/组关系的管理功能保持禁用。临时客户端刷新及原子替换由 OIDC 会话任务实现，不能通过刷新重新启用已经退休的 cookie。

验证范围是 OC 原生生命周期回归，没有新增服务端协议或真实父关系验收。本次不声明完成身份等价、集中部署或旧 Web 移除门槛。

## PR #40 CI 传输超时排查

Ubuntu cgo=1 的 run `38150677565` 在 CLI TLS 下载稳定性 warmup 超过原 120 秒预算。该步骤未运行 console 身份执行器。原失败证据保留；本地 Darwin 稳定性 537 项、Linux/arm64 稳定性 538 项及 400 组密集上传/下载均通过，但不替代 Ubuntu/amd64 cgo=1，也不足以确认根因已修复。

传输超时仍使验收失败，不自动重试、不放宽预算。超时后对本次拥有的 CLI 子进程发 SIGQUIT，并在最多 5 秒清理窗口内提取函数名白名单，原始输出、参数和路径不进入报告；无可用栈时保留空列表。传输时间截止在超时发生处，额外定位耗时单独计入清理。后续发生同类失败可据函数栈继续定位。
