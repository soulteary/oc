# Real protocol CI acceptance

The `core-integration` job runs `buildscripts/test-real-protocol-ci.py` immediately after building its unpatched pinned OtterIO module. It uses that same binary rather than any patched legacy fixture. The existing Linux/macOS × CGO 0/1 matrix is unchanged. The protocol step has a nine-minute timeout; individual wrappers have 240/120/120-second limits and ten-second termination grace periods. Existing transport and performance budgets remain in place.

The three checks are independent. A failure does not prevent the other checks from running, and every completed check is persisted to `console-real-protocols.json`, uploaded by the existing `always()` artifact step. Preparation failures also produce a report. A requested termination kills the wrapper-owned process group and records interruption; forcible operating-system kills cannot run cleanup handlers.

- Range runs single HTTP, split HTTP and split TLS, verifies historical versions and a current-object-only user's historical-read denial, and retains conditional/full-download checks.
- Diagnostics runs `TestDiagnosticsRealServer`: an administrator gets a snapshot, while an ordinary `readwrite` IAM user gets a 403 through its own client. It does not fall back to administrator credentials.
- OIDC runs `TestOtterIOSTSIntegration` explicitly with `OC_OIDC_TEST_SERVER` and a controlled TLS issuer. It verifies an allowed read, session-policy read narrowing, inability to expand a readonly role into write access, and same-subject refresh. This is protocol acceptance, not browser login or external-provider certification.

Go JSON events must contain both `run` and `pass` for the exact required test, without `skip` or `fail`. Ordinary `go test` success or an absent/skipped opt-in test cannot satisfy the acceptance. Wrapper unit tests run in the CI step and cover skipped/absent tests, field-order-independent failure evidence, command-start failures, continuation and timeout.

The report contains binary and harness SHA256 values, declared server source/state/kind, platform, durations, structural test names, whitelisted script/line locations and exception classes, and a whitelist of Range counters/statuses. It never retains raw command output, fixture logs, request bodies, credentials or tokens. Failure evidence therefore identifies the protocol and failed test without exposing raw upstream errors. Range reports are embedded only through whitelisted fields; their temporary sidecar report is not separately uploaded.

`sourceBinding` explicitly records that the source declaration and binary digest are separate evidence. The workflow establishes its module-build provenance by downloading the pinned module, copying it without patches, building with `-mod=readonly`, and running `go mod verify`. A release asset or patched fixture supplied outside that workflow must use its actual `--source-kind` and `--source-state`; a caller-supplied source SHA does not certify a clean source build.

Local macOS arm64 acceptance on 2026-10-11 passed all three protocols against the unpatched `bcc238bc4c2cc3a21aae05b23321bfdb1b4aad05` module build. A separate acceptance also passed against the official Oct 10 server asset (base `8cc518b31ac8b69c8f855e19b4bd027f44275c47`, source state `modified`). These local executions used a current console and the Oct 10 release CLI for fixture setup. They do not certify the full CI matrix, browser OIDC sessions, ordinary-user information equivalence or eligibility to remove the old Web.

One additional local pinned-server execution failed in Range after approximately 0.96 seconds while diagnostics and STS still passed. The original failed report was preserved (`oc-round2-pinned-protocols-final.json` in the local temporary evidence directory); subsequent independent disposable fixtures passed, but the original failure was not reproduced or localized. This does not establish that Range fixture flakiness has been eliminated. Range now saves a phase/profile/exception-class report on failure, and the wrapper preserves those whitelisted fields without accepting a partial profile as success. No automatic retry was added.
